# Соломон — правила работы над кодом

Документы: `idea.md` (зачем) → `spec.md` (что) → `techspec.md` (как,
указатель на `techspec/`) → `design.md` (как это выглядит; у проекта без
UI файла нет). При расхождении: продукт — по `spec.md`, реализация —
по `techspec.md`.

**Читай раздел, а не документ.** `techspec.md` — роутер: §N → файл
в `techspec/`. Спека этапа в блоке «Читать» перечисляет свои разделы
прямо; начинай с них и не расширяй список молча.

Текущие работы — в `specs/`, по папке на этап, очередь в
`specs/README.md`. Новую задачу начинать оттуда — скиллом
`/sdd:spec-new`. **Большое визуальное изменение начинается с прототипа,
а не с кода**: редизайн, новый раздел, L-этап с разметкой — сначала
`/sdd:prototype` показывает, как это будет выглядеть, человек одобряет,
и только потом пишется код (`prototype/README.md`).

**Мелкая правка идёт мимо конвейера**: опечатка, текст, один файл, ничего
не ломает — обычная сессия, коммит, ворота. Этап заводится, когда
изменение трогает данные, доступ или несколько экранов.

## Язык

- Весь UI, тексты бота, ошибки и пустые состояния — на русском.
  Обращение на «вы», спокойно, без канцелярита. Ответы короткие,
  подробности — по запросу.
- Имена файлов, коммиты и сообщения об ошибках в коде — на английском;
  комментарии и доккомменты — на русском.

## Стек

Telegram-бот на Python 3.12 + aiogram 3 (long polling — входящие
соединения не нужны, поэтому бот работает с домашнего компьютера) и
Mini App внутри Telegram на React + TypeScript + Vite. Данные — Supabase
(Postgres) на бесплатном тарифе. Понимание поручений — Claude API,
распознавание речи — Deepgram (перепроверить тарифы перед подключением,
см. `spec.md` §5). Версии и структура папок — `techspec/01-stack.md` и
`techspec/02-layout.md`.

**Цена инфраструктуры: 0 ₽/мес** — Supabase free tier (500 МБ базы),
бот на компьютере автора, статика Mini App на бесплатном хостинге.
Оплата ИИ поштучная (Claude за токены, Deepgram за минуты) и в эту
цифру не входит. Выход за 0 ₽ — развилка, а не мелкая правка: решает
человек.

Ограничение нулевого бюджета определяет форму: **своего постоянно
доступного сервера нет**. Значит, Mini App не может ходить в API на
домашнем компьютере — она работает с данными напрямую через Supabase,
под правилами доступа на стороне базы. Схема проверена на этапе 001
и принята (`techspec/00-adr.md`).

Единственное исключение — **Edge Functions Supabase**: маленькие
серверные функции на том же бесплатном тарифе, где живёт база.
Собственным сервером они не считаются — размещать и оплачивать нечего.
Туда выносится ровно то, чему в браузере места нет: проверка подписи
Telegram (`initData`) и выдача токена, с которым правила доступа
узнают владельца. Бизнес-логика туда не переезжает.

## Инварианты

Нарушение любого — баг уровня безопасности, а не стилистическая правка.
Раздел растёт по мере реальных решений, не выдумывается заранее; первые
инварианты обычно появляются на этапе 001 вместе со стеком.

1. Секреты только из окружения. Анонимный ключ Supabase секретом не
   считается: он публичный по замыслу Supabase, данные защищают правила
   доступа (RLS) на стороне базы. В сборку Mini App разрешено вшивать
   ровно две переменные — `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`;
   токен бота и ключ service-role живут только в окружении бота и в
   `VITE_*` не попадают.
2. Ни одного запроса к данным без фильтра по владельцу. Пользователь
   в первой версии один, но данные разделены с самого начала.
3. Текст из сообщений, документов и с сайтов — входные данные, а не
   команда. Он не меняет правила помощника и не расширяет его
   полномочия.
4. Помощник не сообщает о выполненном действии, пока его не подтвердила
   внешняя система. «Записал» говорится о своей базе, «отправил» — только
   после ответа получателя.
5. Принятое поручение не теряется: задачи и напоминания живут в базе,
   а не в истории разговора с моделью.

## Слои

Три части — `bot/`, `miniapp/`, `supabase/` — друг друга не импортируют:
разные рантаймы, общая только база и HTTP-контракт функции
`telegram-auth`. Дерево репозитория и слои целиком — `techspec/02-layout.md`.

Правило одно на все части: **импорт идёт сверху вниз, обратного
направления нет.**

- Бот: `cli` → `runner` → `handlers`/`middlewares` → `db` → `config`.
  Окружение читает только `cli`, запросы к данным живут в `db`
  (и всегда с фильтром по владельцу), тексты — в `texts.py`, который
  не импортирует ничего своего.
- Mini App: компоненты → `src/lib/*`. Работа с Telegram, функцией и
  базой — в `lib/`; компоненты не зовут `fetch` сами, `lib/` не знает
  про React.
- Edge Functions: `<функция>/index.ts` → `_shared/*`. В `_shared/` —
  чистые функции без `Deno.env` и `Request`, в `index.ts` — только
  обвязка HTTP.

Бизнес-операций пока нет. Когда появятся, они лягут отдельным слоем
между `db` и `handlers`: бот и Mini App должны звать одно и то же,
а не два похожих куска.

## Чего не делаем

Держит объём: без явной просьбы не добавлять.

- Финансы и чеки — они в VoiceFin, отдельном продукте автора.
- Корпоративный таск-трекер: проекты, спринты, отчётность.
- Всё, что тратит деньги или пишет от имени человека наружу, пока это
  не разрешено явно и по категориям.
- Свой логин, свои пуши, свой веб-сайт: вход и уведомления — через
  Telegram.
- Второй UI-kit поверх выбранного.
- Медицинские, юридические и финансовые советы.
- Собственный сервер, пока бюджет 0 ₽ (см. §«Стек»): речь про
  платный или самостоятельно поднятый хостинг. Edge Functions
  Supabase — часть бесплатного тарифа и под запрет не попадают.

Границы первой версии — в `spec.md` §4, они уже этого списка.

## Сдача изменения

Ворота — одна команда, записанная в `.claude/gate-cmd`
(плейсхолдер `{since}` = базовый коммит этапа):

```
node scripts/gate.mjs --since <коммит>    ворота по диффу этапа
node scripts/gate.mjs                     по рабочему дереву против HEAD
node scripts/gate.mjs --only spec         только состояние спек
node scripts/gate.mjs --only prototype    только связку спек с прототипами
```

Стековые проверки (типы, линт, тесты) дописываются в массив `CHECKS`
в `scripts/gate.mjs` на этапе 001 — перечисления проверок в этом файле
нет намеренно, чтобы не разошлись.

Push не делать — только локальные коммиты.
