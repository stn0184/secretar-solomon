# Соломон

Личный ИИ-секретарь в Telegram: принимает поручения голосом, текстом и
фотографией, понимает их обычным языком, сохраняет и напоминает в срок —
чтобы человек не держал свои дела в голове.

Документы: `idea.md` (зачем) → `spec.md` (что) → `techspec.md` (как) →
`design.md` (как выглядит). Правила работы — `CLAUDE.md`. Очередь работ —
`specs/README.md`. Визуал большого изменения одобряется прототипом до
кода — `prototype/README.md`.

## Как запустить

Бот живёт на сервере и работает там круглосуточно — как он туда
попадает, в разделе «Бот на сервере» ниже. На этом компьютере
`solomon-bot` не запускается, пока работает серверный: процесс бота с
этим токеном должен быть один (`techspec/16-server.md` §16.3).

Нужны [uv](https://docs.astral.sh/uv/) и Node 24. Перед первым запуском
скопируйте `.env.example` в `.env` и заполните значения — без них процесс
не стартует и скажет, какой переменной не хватает. Кроме токена бота и
ключей Supabase там три значения для разбора поручений: `ANTHROPIC_API_KEY`
(ключ Claude, тратит деньги), `DEEPGRAM_API_KEY` (ключ Deepgram — им
распознаются голосовые и кружки, тоже тратит деньги) и `OWNER_TIMEZONE` —
часовой пояс владельца в виде `Asia/Yekaterinburg`, без него «в пятницу»
не превратить в дату.

```bash
npm --prefix miniapp run dev           # Mini App: адрес печатает Vite
uv run --directory bot solomon-bot     # бот — только для отладки, серверный остановлен
```

Напоминания приходят, пока бот запущен: цикл отправки живёт в том же
процессе, что и опрос Telegram. Бот не работал (перезапуск, сбой
сервера) — созревшее не пропадает, оно лежит в базе и уходит первым
тиком после запуска.

Схема базы — миграции в `supabase/migrations/`: применяются
`supabase db push` из корня репозитория или тем же SQL в редакторе панели
Supabase. Первое подключение проекта — по чек-листу `supabase/README.md`.

Жива ли база — `uv run --directory bot solomon-health`.
Проверки перед коммитом — `node scripts/gate.mjs` (см. `CLAUDE.md`
§«Сдача изменения»); чистые функции Mini App отдельно —
`npm --prefix miniapp test`.

Как помощник понимает поручения — `uv run --directory bot pytest -m live`:
десять русских примеров уходят в Claude по-настоящему и сверяются с
ожидаемым разбором. Нужен ключ, стоит денег, в воротах не участвует.

## Публикация Mini App

Приложение живёт на GitHub Pages репозитория (`techspec/07-deploy.md`):
push в `main` собирает его workflow `.github/workflows/pages.yml` и
выкладывает по адресу `https://<user>.github.io/<repo>/`. Настраивается
один раз:

1. **Репозиторий на GitHub** — публичный: на бесплатном тарифе Pages
   работает только для публичных репозиториев. Секретов в репозитории
   нет (`.env` не коммитится), так что это безопасно.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. **Settings → Secrets and variables → Actions → New repository secret**,
   два секрета с теми же значениями, что в `.env`: `VITE_SUPABASE_URL`
   и `VITE_SUPABASE_ANON_KEY`. Оба публичные по замыслу Supabase; ключ
   service-role и токен бота сюда не кладутся никогда.
4. **Push в `main`** (по правилу `CLAUDE.md` §«Сдача изменения»). Вкладка
   Actions → «pages» должна позеленеть; адрес — в шаге deploy. Сборка с
   секретом внутри (`service_role`, токен бота, ключ Claude) падает до
   публикации — так и задумано.
5. **Миграции 005–007** должны быть применены к базе (`supabase db
   push`), иначе кнопка «Сделано», вкладка «О себе» и карточка задачи
   в приложении будут отвечать отказом (007 добавляет колонки источника,
   которые приложение читает).
6. **Кнопка меню в BotFather**: `/mybots` → бот → Bot Settings → Menu
   Button → вставить адрес Pages, назвать «Задачи». После этого кнопка
   слева от поля ввода в чате с ботом открывает приложение.
7. **Проверить вживую**: открыть из Telegram — список задач в теме
   мессенджера; `curl -sI https://<user>.github.io/<repo>/` отвечает 200.

Репозиторий переименован — меняется адрес: workflow подхватит новое имя
сам, а в BotFather адрес правится руками. Репозиторий вида
`<user>.github.io` живёт в корне — тогда `VITE_BASE_PATH` в workflow
ставится в `/`.

## Чтение чатов

Соломон читает выбранные вами личные чаты Telegram — официальным путём
«Автоматизация чатов», без права писать (`techspec/25-chats.md`). Из
переписки он записывает договорённости — кто что обещал — и напоминает,
если вы кому-то не ответили. Группы, каналы и переписка до подключения ему
не видны.

**Подключить** — один раз:

Telegram держит в «Автоматизации чатов» только одного бота: если там уже
стоит другой (у владельца — Partner Assistant), Соломон его вытеснит.
Чтобы работали оба, подключайте через Partner Assistant — ниже. Оба пути
коротко называет команда `/chats` в Соломоне.

1. В [@BotFather](https://t.me/BotFather): `/mybots` → бот Соломона →
   Bot Settings → Secretary Mode (раньше называлось Business Mode) →
   Turn on. Без этого бота не выбрать в настройках.
2. В Telegram: Настройки → Автоматизация чатов → «Чат-бот» — имя бота
   Соломона.
3. Там же — какие чаты он читает: все личные, кроме исключённых, или только
   выбранные.
4. Права бота — отвечать, помечать прочитанным и прочие — снять все: читать
   они не нужны, а писать в ваши чаты Соломон не должен и не будет.
5. Соломон пришлёт в свой чат вопрос о согласии: что читает, куда
   отправляет, сколько хранит. «Согласен» — начинает читать новые
   сообщения. До ответа сообщения не хранятся и теряются.

**Что дальше.** Разговор затих на 20 минут — Соломон разбирает его и
пишет «Из переписки с Игорем (Telegram) записал: …», под каждым делом —
кнопка «Убрать». Вам задали вопрос, а вы три часа не написали в этот чат —
один раз напомнит. Под обоими сообщениями — «Открыть чат»: ссылка на чат
с этим человеком (у MAX её нет). С 22:00 до 08:00 молчит до утра. Переписка хранится 7
дней, дела — обычными задачами в списке. На сервере ничего настраивать не
нужно: бизнес-обновления бот запрашивает у Telegram сам.

**Отключить** — в тех же настройках «Автоматизация чатов»: убрать бота или
чаты. Перестать читать, не отключая, — кнопка «Больше не читать» под
вопросом о согласии.

### Через Partner Assistant

Если в «Автоматизации чатов» стоит Partner Assistant, Соломона туда не
ставят: Partner Assistant с вашего разрешения передаёт ему переписку
функцией базы по **ключу передачи** (`techspec/28-relay.md`). Ни ключа
service-role, ни доступа к таблицам Соломона у него нет. Нужна версия
Partner Assistant с передачей Соломону — это его этап в его проекте.

Один раз:

1. Ключ передачи — длинная случайная строка, например
   `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
   Тот же ключ — в `.env` Partner Assistant.
2. В `.env` Соломона — `CHAT_RELAY_KEY=<ключ>` и
   `PARTNER_BOT_USERNAME=<имя бота Partner Assistant без @>`. Нужны оба;
   нет хотя бы одного — приём выключен, `/chats` предлагает только прямое
   подключение.
3. Миграция этапа 028 — в базу (`supabase db push`), потом выложить бота с
   ключами: `node scripts/deploy-bot.mjs --env`. При запуске бот пишет в
   базу хэш ключа — сам ключ туда не уходит — и отзывает прежние.
4. Проверить канал: `node scripts/relay-check.mjs`. Это тот же вызов, что
   делает Partner Assistant, с пустой пачкой — в базу ничего не пишется;
   нужны ещё `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в `.env`.
   «Канал работает» — ключ принят, чужой ключ отвергнут.
5. В Соломоне — `/chats` → «Открыть Partner Assistant» → «Разрешить».
6. Соломон в течение минуты спросит согласия — тот же вопрос с припиской
   «переписку передаёт Partner Assistant». «Согласен» — начинает принимать;
   до ответа переданное не хранится, и Partner Assistant его не повторяет.

Дальше всё как выше: «Из переписки с Игорем (Telegram) записал: …» и «Вы
не ответили». Ответы, которые Partner Assistant пишет от вашего имени, —
ваши: снимают «ждёт ответа», обещанное в них — ваше обещание. Голосовые —
по расшифровке Partner Assistant.

Какие чаты: те, что открыты боту в настройках Telegram. Чтобы Соломон
читал больше, добавьте чаты там; Partner Assistant в добавленных молчит,
пока вы не включите их у него. Partner Assistant работает на вашем
компьютере: выключен компьютер — Соломон чатов не видит (Telegram держит
недоставленное около суток).

Запретить передачу — в Partner Assistant: приём останавливается.
Сменить ключ — заменить в обоих `.env` и выложить Соломона с `--env`,
прежний отзывается при запуске.

## Instagram

Соломон читает Direct вашего бизнес-аккаунта в Instagram так же, как
личные чаты Telegram: записывает договорённости и напоминает, если вы
кому-то не ответили (`techspec/26-instagram.md`). Отвечать в Direct,
ставить реакции и читать комментарии он не будет. Личный аккаунт не
подойдёт: Meta отдаёт сообщения только профессиональным — бизнес или
автор.

**Подключить** — один раз:

1. Аккаунт — профессиональный: в Instagram меню ≡ → «Настройки и
   действия» → «Тип аккаунта и инструменты» → «Переключиться на
   профессиональный аккаунт».
2. Там же — доступ к сообщениям: «Сообщения и ответы на истории» →
   «Подключённые инструменты» → «Разрешить доступ к сообщениям». Без него
   Meta Direct не отдаёт, и Соломон напишет «Instagram не пускает меня к
   сообщениям Direct».
3. На [developers.facebook.com](https://developers.facebook.com/apps) —
   создать приложение типа **Business** со сценарием «Manage messaging and
   content on Instagram». Проверка приложения (App Review) не нужна: своё
   приложение читает свой аккаунт.
4. В приложении: Instagram → «API setup with Instagram business login» →
   добавить свой аккаунт и нажать **Generate token** рядом с ним, войти в
   Instagram и разрешить права `instagram_business_basic` и
   `instagram_business_manage_messages`. Аккаунт должен быть у приложения
   в роли — владельца или тестировщика Instagram (App roles → Roles); если
   Meta пришлёт приглашение тестировщика, примите его в Instagram.
5. Ключ из шага 4 живёт 60 дней. Вставить его в `.env` на этом
   компьютере строкой `INSTAGRAM_TOKEN=…` и выложить бота с ключами:
   `node scripts/deploy-bot.mjs --env`.
6. Соломон пришлёт вопрос о согласии. «Согласен» — он прочитает
   сообщения Direct за последние сутки и дальше читает новые раз в 5
   минут. До ответа Direct не читается.

**Что дальше.** Всё как у чатов Telegram (раздел «Чтение чатов» выше), с
пометкой площадки: «Из переписки с @oleg (Instagram) записал: …», «Вы не
ответили @oleg (Instagram) — …». Ответы на истории, групповые чаты и
запросы на переписку старше 30 дней Соломон не видит, правки и удаления в
Direct — тоже.

**Ключ продлевается сам.** Соломон держит действующий ключ в файле на
сервере (`/opt/solomon/state/instagram.json`, читает его только служба
бота) и продлевает, когда до конца остаётся меньше 10 дней. В `.env`
ничего менять не нужно.

**Бот попросил новый ключ** («Instagram отключился: нужен новый ключ…»)
— ключ истёк или отозван, и Соломон перестал читать Direct. Повторить
шаг 4, заменить `INSTAGRAM_TOKEN` в `.env` и выложить
`node scripts/deploy-bot.mjs --env`. На сервере ничего чистить не нужно:
новый ключ в `.env` главнее файла на сервере.

**Отключить** — убрать строку `INSTAGRAM_TOKEN` из `.env` и выложить с
`--env`. Перестать читать, не убирая ключ, — кнопка «Больше не читать»
под вопросом о согласии.

## MAX

Личные чаты MAX официально не читаются, поэтому у Соломона в MAX свой бот
(`techspec/27-max.md`). Он видит то, что вы ему пересылаете или пишете сами,
и группы, куда вы его добавили. Что записал — Соломон пишет сюда, в
Telegram, как из чатов Telegram: «Из переписки с Игорем (MAX) записал: …» с
кнопками «Убрать». В MAX бот отвечает только «Принял, итог пришлю в
Telegram.», в группы не пишет. «Вы не ответили…» по MAX не приходит: бот не
видит, ответили ли вы в самом MAX.

**Подключить** — один раз:

1. Завести бота на [платформе MAX для партнёров](https://business.max.ru/self):
   профиль самозанятого (подтверждение через Госуслуги), затем «Чат-боты» →
   создать бота. Модерация — до 48 часов.
2. Токен бота: «Чат-боты» → ваш бот → «Перейти» → «Расширенные настройки» →
   «Настроить» (или команда «Получить токен» в боте «MAX для бизнеса»).
   Вставить в `.env` на этом компьютере строкой `MAX_BOT_TOKEN=…`. Токен —
   секрет: никому не пересылать. Подписку на вебхук боту не заводить: с ней
   MAX не отдаёт события опросом, а Соломон берёт их опросом.
3. Свой id в MAX: найти бота в MAX, нажать «Начать» и написать ему
   «привет». Затем здесь — `uv run --directory bot pytest -m live -k max -s`:
   он напечатает id тех, кто писал боту, ваш — тот, что появился после
   «привет». В профиле MAX этого числа нет. Вставить в `.env` строкой
   `OWNER_MAX_ID=…`.
4. Выложить бота с ключами: `node scripts/deploy-bot.mjs --env`.
5. Написать боту в MAX что-нибудь — Соломон пришлёт сюда вопрос о
   согласии. «Согласен» — бот начинает читать. Пересланное до ответа не
   хранится: перешлите его снова.

**Группы.** На платформе для партнёров: «Чат-боты» → бот → ⋮ →
«Настройки» → «Приватность» — разрешить добавление в групповые чаты. Затем
в MAX: открыть группу → её название → «Участники» → «Добавить участников» —
бот; назначить его администратором с правом «Читать все сообщения»,
остальные права не нужны. Без этого права MAX не показывает боту чужие
сообщения в группе. Соломон читает только группы, где есть вы; добавили
бота в чужую группу — он её не читает.

**Что дальше.** Пересланная переписка ложится в чат по исходной переписке,
ваши сообщения боту — в «MAX: заметки», группа — своим чатом. Затихло на 20
минут — разбор, и сюда приходит, что записано; из заметок — «Из ваших
заметок в MAX записал: …». На первую пачку после 20 минут тишины бот в MAX
отвечает «Принял, итог пришлю в Telegram.» — один раз. Голосовые
расшифровываются. Времени исходных сообщений MAX в пересланном не даёт —
«завтра» в старой переписке считается от момента пересылки. Сертификат
сервера MAX выдан Минцифры; его корневой сертификат лежит в `bot/certs/`,
на сервере ничего ставить не нужно.

**Отключить** — убрать `MAX_BOT_TOKEN` или `OWNER_MAX_ID` из `.env` и
выложить с `--env`. Перестать читать, не убирая бота, — кнопка «Больше не
читать» под вопросом о согласии или «Остановить» бота в MAX.

## Бот на сервере

Бот работает на сервере VoiceFin службой systemd `solomon-bot` от
отдельного пользователя `solomon` (`techspec/16-server.md`). Скрипт
`scripts/deploy-bot.mjs` ходит туда по SSH с этого компьютера по имени
`voicefin-vps` из `~/.ssh/config` — адреса сервера в репозитории нет.
Вход — `root` по ключу: пароль скрипт не спрашивает и зависнуть на нём
не может. Все флаги — `node scripts/deploy-bot.mjs --help`.

**Первая настройка** — один раз:

1. `node scripts/deploy-bot.mjs --setup` — заводит пользователя
   `solomon`, ставит ему uv и Python 3.12, клонирует репозиторий с
   GitHub и ставит зависимости бота. Повторный запуск продолжает с
   несделанного шага и ничего не ломает. Нет на сервере `git` или
   `curl` — скрипт остановится и назовёт их: пакеты системы — хозяйство
   VoiceFin.
2. Остановить бота на этом компьютере — процесс бота один.
3. `node scripts/deploy-bot.mjs --env` — выкладка с ключами: служба
   ставится, автозапуск включается, бот стартует.

**Выкладка нового кода** — после push в `main` с чистыми воротами;
миграции этапа, если есть, — в базу до неё:

```bash
node scripts/deploy-bot.mjs            # pull, зависимости, перезапуск, проверка
node scripts/deploy-bot.mjs --env      # то же и ключи из .env — после их смены
node scripts/deploy-bot.mjs --status   # ничего не меняет: служба, коммит, память, журнал
```

Скрипт откажет до обращения к серверу, если есть незакоммиченные
изменения или `HEAD` не совпадает с `origin/main`: сервер берёт код с
GitHub. После перезапуска он ждёт до 60 с строку `Run polling for bot`
в журнале службы и сверяет коммит на сервере с `HEAD`; не дождался —
показывает хвост журнала. Отката нет: исправление — новым коммитом,
push и выкладкой.

`--env` кладёт на сервер ровно переменные раздела бота из
`.env.example`; значения уходят через stdin `ssh`, в выводе — только
имена. Ключи Mini App, Supabase CLI и секреты функций на сервер не
попадают.

Журнал бота — на сервере:

```bash
ssh voicefin-vps journalctl -u solomon-bot -n 100 --no-pager
ssh voicefin-vps journalctl -u solomon-bot -f      # следить; Ctrl+C — выйти
```

Отладка на этом компьютере — сначала остановить серверного
(`ssh voicefin-vps systemctl stop solomon-bot`), после — поднять его
выкладкой. `TelegramConflictError` в журнале значит, что бот запущен в
двух местах сразу.
