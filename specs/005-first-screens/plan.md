# План этапа 005 — первые экраны Mini App

Порядок файлов и решения по неоднозначностям. Читает ремонтный заход:
он стартует с чистым контекстом и без плана выведет другой.

## Порядок коммитов

1. `plan.md`, статус «в работе» в спеке и таблице.
2. Миграция `supabase/migrations/20260927120000_complete_task.sql` +
   `techspec/03-schema.md` §3.6 + `supabase/README.md` §«Новая миграция».
3. `lib/format.ts` — тесты красным, затем реализация.
4. `lib/tasks.ts` — тест группировки красным, затем реализация; `session.ts`
   (сессия с повторным запросом токена), `supabase.ts` (обёртка запроса
   с повтором при 401 и своими текстами ошибок), `telegram.ts`
   (`BackButton`, `showPopup`, `close`, тема). Тесты на Node → ворота
   (`miniapp:tests`).
5. Компоненты `src/components/*`, `App.tsx`, `styles.css`.
6. Публикация: `vite.config.ts` (`base`), `scripts/check-dist.mjs`,
   `.github/workflows/pages.yml`, `README.md`, `HELP` бота.
7. Документы: `CLAUDE.md` §«Сдача изменения», `techspec/00-adr.md`,
   `techspec/02-layout.md`, `design.md` §1/§3.
8. Закрытие: статус «сделано», архив спеки, архив прототипов 005 и 000,
   бэклог.

## Структура Mini App

```
src/
  App.tsx                 состояние сессии, переключение «список ↔ карточка», BackButton
  styles.css              токены из --tg-theme-*, вёрстка по design.md §1
  components/
    TaskList.tsx          экран списка: загрузка (плашки), пусто, ошибка, группы
    TaskCard.tsx          экран карточки: поля, источник, напоминания, действия
    Header.tsx            заголовок экрана + своя «‹ Задачи» + подпись
    TaskGroup.tsx         заголовок группы капителью + карточка со строками
    TaskRow.tsx           строка задачи: полоска, суть, срок, метки, шеврон
    Chip.tsx              пилюля: high / mine / theirs / review / kind
    Field.tsx             строка «название — значение» карточки
    SourceMessage.tsx     исходное сообщение с датой
    Reminders.tsx         напоминания: отправлено / ждёт
    Actions.tsx           «Сделано» и «Удалить»
    Empty.tsx             пустое состояние с примерами и «Вернуться в чат»
    ErrorNote.tsx         текст ошибки + «Обновить»
  lib/
    telegram.ts           SDK: initData, BackButton, showPopup, close, colorScheme
    session.ts            токен: запрос, срок, повторный запрос (один раз)
    supabase.ts           клиент + `query()`: истёкший токен → новый → повтор; тексты отказов
    tasks.ts              типы, чтение списка, группировка (чистая), карточка, complete, remove
    format.ts             даты словами (пояс устройства), склонения
    *.test.ts             тесты чистых функций на `node --test`
```

Компоненты → `lib/*`; `lib/` не знает React. Экранные компоненты
(`TaskList`, `TaskCard`) получают `db` и колбэки от `App`, сами данные
не запрашивают мимо `lib/`.

## Решения по неоднозначностям

- **Тесты чистых функций — `node --test`, без `vitest`.** Node 24 читает
  `.ts` сам (type stripping), в `supabase/` так уже сделано; новая
  зависимость не нужна. Скрипт `npm test` в `miniapp/package.json`, в
  ворота — `miniapp:tests`. Тест пишется до реализации и показывается
  красным (правило проекта для чистых функций).
- **Слова срока — ровно как у бота** (`texts.py`): «сегодня» только для
  текущего дня, «завтра» не вводится; время показывается лишь при
  `due_precision = time`; год не пишется. Момент сообщения и напоминания —
  всегда с временем (как `format_due_moment`). Без срока — «записано
  24 сентября».
- **Границы групп — по календарному дню устройства**: просрочено — день
  срока раньше сегодняшнего (`day`) или момент прошёл (`time`); сегодня —
  тот же день; на неделе — 1..7 дней вперёд; позже — дальше. `due_precision`
  пустой при непустом `due_at` считается `day`. Идеи и желания — своей
  группой внизу независимо от срока. Внутри группы — новые сверху, как
  говорит спека (по `created_at`), а не по сроку.
- **Карточка не перечитывает задачу**: задача берётся из списка, из базы
  докачиваются сообщение и напоминания (два `select` под RLS). §3.6
  говорит о трёх `select` — третий не нужен, задача уже в руках.
- **Удаление подтверждается тем, что база вернула строку**:
  `delete … select id` — пусто значит задачи уже нет для этого владельца,
  это ошибка на карточке, а не «исчезло». `complete_task` вернул `null` —
  то же самое.
- **Обновление токена** — в `supabase.ts`, одной обёрткой `query()`: перед
  запросом истёкший по локальным часам токен обновляется; ответ 401 /
  `PGRST301` — токен запрашивается заново один раз и запрос повторяется;
  не вышло — отказ текстом, компонент показывает «Обновить». `initData`
  функция принимает сутки, поэтому повторный обмен того же `initData`
  через час законен.
- **Тексты ошибок** собираются в `lib/`, английский хвост Supabase в них не
  попадает; причина — общая (связь / доступ / отказ базы), префикс —
  по операции («Не получилось прочитать задачи», «…закрыть задачу»,
  «…удалить задачу»).
- **Тема**: `--app-bg`, `--surface`, `--line`, `--ink*`, `--accent*`,
  `--urgent` — из `--tg-theme-*` с запасными значениями прототипа; в
  тёмной схеме `--surface` берёт `section-bg-color`, а фиксированные
  пары `--important / --ok / --guess` переключаются атрибутом
  `data-scheme` на `<html>` (ставится из `colorScheme` SDK и на
  `themeChanged`). Вне Telegram схема — из `prefers-color-scheme`.
- **`showPopup`** — подтверждение удаления; вне Telegram или на старой
  версии SDK (< 6.2) — `window.confirm`, чтобы dev-прогон в браузере
  не ломался. `BackButton` — c 6.1, иначе только своя стрелка.
- **`base` в Vite** — из `VITE_BASE_PATH` (`loadEnv`, не `import.meta.env`),
  пусто — `/`. Workflow ставит `/<имя репозитория>/`. Переменная не секрет
  и в код приложения не попадает; инвариант 1 говорит о ключах.
- **Проверка сборки на секреты** — `scripts/check-dist.mjs` без
  зависимостей: ищет `service_role`, `sk-ant-`, токен бота по форме
  `NNNNNNNNN:XXXX…` и разбирает каждый найденный JWT (`eyJ…`) — роль
  `service_role` в клейме тоже провал. Зовётся из workflow до deploy и
  из ворот после сборки (`miniapp:secrets`).
- **Версии actions** (проверены 2026-09-27): `checkout@v7`, `setup-node@v7`,
  `configure-pages@v6`, `upload-pages-artifact@v5`, `deploy-pages@v5`.
  Прогон вживую в этом этапе невозможен — репозитория на GitHub ещё нет.
- **Прототип 000** уезжает в архив тем же коммитом с пометкой «не одобрен,
  заменён 005»; строка бэклога про него удаляется.
- **`design.md` §1/§3** уже заполнены на одобрении прототипа; правятся
  только расхождения с кодом (экранные компоненты в инвентаре, путь
  прототипа в архиве).
