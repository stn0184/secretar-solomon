## Проблема

Часть общения владельца идёт в MAX, и договорённости оттуда в Соломона
не попадают. Личные чаты MAX официально не читаются; официальный бот
видит только написанное ему и группы, куда его добавили.

## Решение

Официальный бот MAX как источник `max` для общей части §25: владелец
пересылает ему переписку или пишет заметку, а бот добавлен в его группы
с правом читать всё. Всё попадает в общее хранилище и разбор; дела и
«Убрать» приходят в Telegram-Соломона. В MAX бот отвечает только
«Принял, итог пришлю в Telegram.». Устройство — §27.

## Чего не делаем

- Не читаем личные чаты владельца в MAX (юзербот отвергнут).
- Не отвечаем в MAX ничего, кроме «Принял…», и не пишем в группы.
- Не ведём «ждёт ответа» по MAX вовсе; каналы не читаем.
- Не ставим ничего на сервер: сертификат — в репозитории.

## Задачи

- [x] Настройки: `MAX_BOT_TOKEN`, `OWNER_MAX_ID` — необязательные; нет —
  источник выключен; `.env.example`, `deploy-bot.mjs`.
- [x] Клиент MAX на httpx: long polling обновлений, ключ в заголовке,
  корневой сертификат Минцифры только для этого клиента; задача asyncio
  рядом с опросом Telegram, остановка вместе с ботом.
- [x] Приём: пересланное — строки переписки с исходным отправителем;
  заметка владельца — чат «MAX: заметки»; группы — `out` по
  `OWNER_MAX_ID`; чужие в личке бота — пропуск; голосовые через Deepgram.
  «Ждёт ответа» по MAX не ведётся вовсе — ни по пересланному, ни по
  заметкам, ни по группам (решение владельца): бот не видит, ответил ли
  владелец в самом MAX. Общая часть 025 даёт этот признак на чат.
- [x] Согласие (сообщение §25.5 про MAX) и «Принял…» один раз на пачку.
  Согласие спрашивается при первом сообщении боту (общий механизм 025);
  пересланное до «Согласен» не хранится — его нужно переслать снова.
  «Принял…» — после 20 минут тишины в личном чате с ботом.
- [x] `README.md` — раздел «MAX»: регистрация на business.max.ru, токен,
  как узнать свой id, как добавить бота в группу с правом читать всё.
- [x] Живой прогон — только когда токен владельца уже в `.env`; иначе
  тесты с подменённым API и пометка в отчёте.

## Приёмка

Подтверждается тестами бота с подменённым API MAX и, если токен есть,
живым прогоном; переписки выдуманные.

1. КОГДА `MAX_BOT_TOKEN` или `OWNER_MAX_ID` не заданы, бот ДОЛЖЕН
   работать как раньше и MAX не опрашивать.
2. КОГДА владелец переслал боту в MAX переписку с договорённостью, в
   Telegram-Соломоне ДОЛЖНО прийти «Из переписки с … (MAX) записал: …»
   с кнопками «Убрать», а в MAX — одно «Принял, итог пришлю в Telegram.».
3. КОГДА в группе с ботом договорились о деле, оно ДОЛЖНО записаться
   так же; «Вы не ответили …» по MAX — ни по группам, ни по
   пересланному, ни по заметкам — НЕ ДОЛЖНО приходить.
4. КОГДА боту в MAX пишет не владелец, бот НЕ ДОЛЖЕН отвечать и хранить.
5. Запросы к `platform-api2.max.ru` ДОЛЖНЫ проходить проверку TLS с
   сертификатом из репозитория, без отключения проверки.
6. КОГДА MAX не ответил, опрос ДОЛЖЕН продолжиться, а пропущенное —
   забраться.
