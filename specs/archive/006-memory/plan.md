## Решения по неоднозначностям

- **Подпись источника** — «с ваших слов» / «из сообщения» (одобрение
  прототипа), не «из поручения» из `techspec/08-memory.md` §8.4; техспек
  правится под одобренное. Подпись выводится из **вида исходного
  сообщения** (`messages.analysis->>'kind' = 'about_me'`), а не из статуса:
  после «Подтвердить» статус меняется, подпись — нет (приёмка).
  Поэтому список читается одним запросом с вложенным источником:
  `source:messages(text, received_at, kind:analysis->>kind)`; записи без
  источника получают «из сообщения».
- **Дата в подписи** — `created_at` записи (у записи без источника иначе
  даты нет), словами через `formatDate`.
- **Конфликт `guess` → `fact`** (`on conflict do update`): вместе со
  статусом обновляется `source_message_id` на новое сообщение `about_me` —
  человек сказал это прямо, и подпись «с ваших слов» должна вести к тому
  сообщению, где он это сказал. `fact` → `guess` не бывает: условие
  `where excluded.status = 'fact' and facts.status = 'guess'`.
- **`source_message_id`** — `references messages(id) on delete set null`:
  память — сведение о человеке, а не часть сообщения; удаление следа не
  должно стирать память.
- **Место вставки фактов в `record_understanding`** — сразу после проверки
  владельца, до ранних `return`: записи пишутся для всех видов сообщений,
  включая `chat` и `about_me` без задачи; повтор идемпотентен по `unique`.
- **Кто читает известные факты** — `UnderstandingService` через
  внедрённого читателя (`KnownFacts`), собирается в `with_client(settings,
  client, db)`. Слои соблюдены: `services` → `db`. `TaskService` о памяти в
  промпте не знает.
- **Порядок известных в промпте** — по `created_at` по возрастанию:
  стабильный список, первые 50.
- **`facts` у `Understanding`** — обязательное поле без значения по
  умолчанию, как остальные (модель заполняет каждое, пустое — `[]`).
  В `messages.analysis` уходит вместе с прочими полями.
- **Ответ на `about_me` с несколькими записями** — «Запомнил: А; Б»
  (через «; »), текст записи дословно от модели, как `review_reason`
  (§5.4 дополняется).
- **Список записей в приложении** — грузится при первом открытии вкладки
  и по «Обновить»; после подтверждения/удаления правится локально по
  ответу базы, без перечитывания. Лимита нет (десятки записей).
- **Вкладки** — `position: fixed` внизу, экран получает нижний отступ на
  их высоту; в карточке задачи вкладок нет и отступа тоже.
- **Подтверждение удаления записи** — `showPopup` с текстом про память
  («исчезнет из памяти помощника, сообщение в переписке останется»);
  вне Telegram — `window.confirm`, как у задачи.
- **`HELP` бота не меняется**: спека разрешает ровно два новых текста.
  Замечание в отчёт: справка не упоминает вкладку «О себе».
- **Живой прогон**: у примеров памяти в `understanding.jsonl` поля
  `facts` (`fact` / `guess` / `none`) и необязательный `known` — список
  строк «категория: текст» для промпта; сервис в живом тесте собирается на
  каждый пример со своим `known`.
