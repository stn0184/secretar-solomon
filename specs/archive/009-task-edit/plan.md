## Решения

**Имена в базе.** Таблица `owner_settings (owner_telegram_id bigint primary
key, timezone text not null, updated_at)`, RLS «owner only» как у прочих.
Бот пишет пояс функцией `save_owner_timezone(owner_telegram_id, timezone)`
(только `service_role`, `on conflict on constraint owner_settings_pkey`);
негодное имя пояса — отказ базы (`now() at time zone` проверяет его), а не
запись, на которой потом сломается правка. Отметка «срок перенесён» —
колонка `tasks.due_moved_at timestamptz` (`clock_timestamp()` правки):
момент, а не флаг, — по нему бот снимает ровно прочитанное.

**`reminder_plan`** — `language sql stable`, `returns table (stage text,
fire_at timestamptz)`, упорядочено по `fire_at`. Права: `authenticated`
(зовёт `edit_task` под ролью владельца) и `service_role` (бот); у
`public`/`anon` забраны. Данных не читает — владелец ему не нужен.

**`edit_task(task_id, changes)`** принимает ключи `title`, `due_at`,
`due_date`, `kind`, `priority`, `promise`, `people`; незнакомый ключ,
`due_at` вместе с `due_date` или пустая суть — исключение (отказ целиком).
Точность срока клиент не шлёт — она следует из ключа: `due_at` момент →
`time`, `due_date` → `day` (18:00 в поясе владельца), `due_at = null` →
срока нет. Изменение считается по значениям (`is distinct from`), а не по
наличию ключа: тот же день ещё раз — не перенос.
- **Перепланирование** — когда изменились `due_at`, `due_precision` или
  `kind`. **Отметка «перенёс»** — когда изменились `due_at` или
  `due_precision`: час, добавленный к дню, — это новый срок для человека
  и новое расписание (вместо 09:00 — за час), о нём стоит сказать.
- **Нет пояса** — отказ, если правке нужно перепланирование (а не только
  смена срока): смена вида идея → задача с днём без пояса дала бы
  расписание без утренней ступени — молча хуже отказа (§11.3).
- Строка задачи блокируется `for update`: правка и «Сделано» из чата не
  перекрещиваются.

**Бот: функции цикла** — `moved_tasks(owner_telegram_id)` (активные с
отметкой: суть, срок, точность, `due_moved_at`, ближайшее неотправленное
напоминание) и `clear_due_moved(owner_telegram_id, task_id, seen)` —
снимает, только если отметка всё ещё `seen`; обе только `service_role`.

**Планировщик в боте.** `Planned` переезжает в `db/reminders.py` (это
строка ответа базы; `services` его импортирует, обратного импорта нет).
Протокол `Planner(*, due_at, due_precision, kind, now) -> list[Planned]` —
в `services/reminders.py`; пояс подставляет сборка из `Settings`.
`TaskService` получает `planner` обязательным аргументом: без него бот
молча писал бы задачи без напоминаний. Планировщик зовётся, только когда
пишется задача (виды `task/idea/wish`) или поправка; разговор и «о себе» —
без похода в базу. Запись «как есть» при отказе модели — без срока, план
пуст, похода тоже нет. Отказ планировщика — `NOT_SAVED`, разбор не пишется.
`fire_at` из базы приходит в UTC — строка «Напомню» переводит его в пояс
владельца, как и раньше.

**Строка «Перенёс».** Тик: сначала созревшие напоминания, потом строки о
переносе — так «Напомню» не назовёт ступень, которая только что ушла.
Строка уходит без кнопки «Сделано» (это не напоминание) — отдельным
замыканием `announce` из `runner.py`. Срок в прошлом (`due_at <= now`) —
без «Напомню»; ближайшее напоминание в прошлом (не ушло, бот лежал) тоже
не называется. Сбой отправки — отметка остаётся до следующего тика; сбой
снятия — строка в журнал (дубль лучше потери, как у напоминаний).

**Mini App.** `Task.openQuestion: {text, askedAt} | null` из колонок;
свежесть (сутки) — чистая `questionOf(task, now)`. Черновик формы —
`TaskDraft` из строк полей ввода (`day`, `time`, `noDue`, `people` строкой);
`draftOf(task)`, `validateDraft(draft)`, `taskChanges(task, draft)`,
`dueHint(draft, now)` — чистые в `tasks.ts`; перевод полей ввода ↔ `Date`
и момент со смещением — в `format.ts`. «Без срока» снят, а день не
выбран — «Выберите день или отметьте «Без срока».» (спека называет только
пустую суть; молча снять срок из-за пустого поля хуже). Подсказка под
сроком называет и вид: у идеи и желания — «Об идеях и желаниях не
напоминаю.» «Сохранить» без изменений на задаче с пометкой или вопросом
(любой давности — колонка не пуста) шлёт пустой `changes`; без пометки —
форма закрывается без запроса.

**Состояние формы** — в `App.tsx`: `editing` и признак «есть
несохранённое» (ref, его сообщает форма); «назад» Telegram, своя
«‹ Задача» и «Отмена» идут одним `back()`. Карточка остаётся владельцем
докачанных данных: форма получает исходное сообщение от неё, после
«Сохранить» `App` заменяет задачу в списке и в карточке, карточка
перечитывает напоминания (эффект по новой задаче). `Actions` получает
вид `save` и необязательную вторую кнопку вместо «Удалить».

**Прототип vs спека.** Расхождений нет; подпись «Срочность» в форме при
«Приоритет» в карточке — как одобрено на прототипе.
