# §2. Раскладка репозитория и слои

Три части в одном репозитории, каждая запускается отдельно. Версии —
§1, решения по связке Mini App с базой — §0.

```
bot/                     Telegram-бот, Python 3.12, long polling
  pyproject.toml         зависимости, ruff, mypy, pytest
  uv.lock
  src/solomon/
    cli.py               точки входа: solomon-bot, solomon-health
    config.py            разбор окружения в Settings
    texts.py             тексты для человека, на русском
    handlers.py          ответы на команды
    middlewares.py       калитка владельца (инвариант 2)
    runner.py            сборка Dispatcher и long polling
    db/
      client.py          клиент Supabase на ключе service-role
      health.py          «жива ли база»
  tests/                 pytest; сеть не трогается

miniapp/                 Mini App внутри Telegram, React + TS + Vite
  index.html             подключает telegram-web-app.js
  vite.config.ts         envDir = корень репозитория
  eslint.config.js
  src/
    main.tsx             точка входа
    App.tsx              экран-заглушка
    styles.css           цвета из --tg-theme-*
    lib/
      telegram.ts        доступ к SDK Telegram
      session.ts         обмен initData на токен доступа
      supabase.ts        клиент базы с этим токеном

supabase/                база и Edge Functions
  config.toml            настройки для Supabase CLI
  functions/
    _shared/             чистая логика: HMAC, initData, JWT
    telegram-auth/       HTTP-обвязка функции
  types/deno.d.ts        кусок API Deno для tsc

scripts/gate.mjs         ворота: стековые проверки + состояние спек
specs/  techspec/  prototype/   документы и очередь работ
.env.example             один файл на все части, значений нет
```

### 2.1 Границы частей

`bot/`, `miniapp/` и `supabase/` **не импортируют друг друга** — ни
прямо, ни через общий пакет. Части живут на разных рантаймах (CPython,
браузер, Deno), и связывать их одной библиотекой значит держать сборку
ради нескольких строк.

Общего у них ровно три вещи:

- корневой `.env` (образец — `.env.example`): бот читает его при запуске,
  Vite подставляет `VITE_*` в сборку;
- база: части видят одни и те же данные, но через разные ключи и под
  разными правилами;
- HTTP-контракт `telegram-auth` — Mini App шлёт `initData`, получает JWT
  (`supabase/README.md`).

Расходятся эти контракты только осознанно: поле в ответе функции —
правка обеих сторон в одном коммите.

Ключи разделены по частям и пересекаться не должны: у бота —
`SUPABASE_SERVICE_ROLE_KEY` (обходит правила доступа, поэтому в браузер
не попадает никогда), у Mini App — `VITE_SUPABASE_ANON_KEY`, у функции —
токен бота и секрет подписи JWT в секретах проекта Supabase
(инвариант 1).

### 2.2 Слои бота

Импорт идёт сверху вниз, обратного направления нет:

```
cli ──▶ runner ──▶ handlers, middlewares ──▶ db ──▶ config
                        └──────▶ texts
```

- `config.py` — чистый разбор окружения: получает `Mapping`, возвращает
  `Settings`, сам ничего не читает. Поэтому его поведение проверяется
  тестами без подмены окружения.
- `cli.py` — **единственное** место, где трогается `os.environ` и файл
  `.env`. Всё остальное получает готовые `Settings`.
- `db/` — доступ к данным. Запросы к данным владельца пишутся здесь
  и всегда с фильтром по владельцу (инвариант 2).
- `handlers.py`, `middlewares.py` — тонкий слой над aiogram: берут
  зависимости из workflow data диспетчера, тексты — из `texts.py`,
  собственных настроек не читают.
- `texts.py` — листовой модуль: ничего из `solomon` не импортирует,
  поэтому тексты можно править, не боясь за поведение.
- `runner.py` — сборка: кто во что включён и какое middleware стоит
  на входе.

Бизнес-операции (разбор поручений, задачи, напоминания) появятся
следующими этапами и лягут между `db` и `handlers` отдельным слоем —
чтобы Mini App и бот вызывали одно и то же, а не два похожих куска.

### 2.3 Слои Mini App

```
main.tsx ──▶ App.tsx (и будущие компоненты) ──▶ src/lib/*
```

`src/lib/` — вся работа с внешними системами: Telegram, Edge Function,
база. Компоненты не зовут `fetch` и не трогают `window.Telegram`
напрямую, а `lib/` ничего не знает о React и не импортирует компоненты.

Отказ — это текст на экране, а не исключение: `session.ts` возвращает
результат с сообщением на русском, компонент его показывает.

### 2.4 Слои Edge Functions

```
telegram-auth/index.ts ──▶ _shared/*
```

`_shared/` — чистые функции: считают HMAC, разбирают `initData`,
подписывают JWT. Они не читают `Deno.env` и не знают про `Request`,
поэтому проверяются обычными тестами на Node.

`index.ts` каждой функции — только обвязка: читает секреты из окружения,
переводит ошибки в коды ответа, ничего не вычисляет сам.
