# §7. Публикация Mini App

Где живёт статика Mini App, как попадает туда и как её открывает
Telegram. Бот и база к разделу отношения не имеют: бот работает с
компьютера владельца (§2), база — в Supabase.

### 7.1 Хостинг — GitHub Pages

| Что | Значение | Почему |
| --- | --- | --- |
| Хостинг | GitHub Pages репозитория проекта | Бесплатно, аккаунт GitHub у владельца есть, ничего нового заводить не нужно (решение владельца, ADR) |
| Адрес | `https://<user>.github.io/<repo>/` | Vite собирается с `base: '/<repo>/'`; путь берётся из переменной сборки, чтобы форк или переименование не ломали ссылки |
| Сборка | GitHub Actions, workflow `.github/workflows/pages.yml`: `npm ci` → `vite build` → deploy в Pages | Push в `main` публикует автоматически; локально `dist/` не коммитится |
| Переменные сборки | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` — секреты репозитория (Settings → Secrets → Actions) | Инвариант 1: в репозитории значений нет; в сборку попадают ровно эти две — оба публичные по замыслу Supabase |
| Маршрутизация | Один `index.html`, экраны переключаются состоянием, без роутера по URL | Pages не умеет SPA-fallback без хака с `404.html`; Telegram открывает всегда корень |

### 7.2 Push

Правило «push не делать» (`CLAUDE.md`) уточняется: **push в `main`
делается ради публикации** — по команде владельца или когда закрыт
этап с изменениями Mini App. Push — это и есть деплой, поэтому перед
ним ворота должны быть чисты. Ветки, PR и push промежуточных коммитов
не заводятся: репозиторий один, человек один.

### 7.3 Как Telegram открывает приложение

Адрес Pages задаётся боту в @BotFather один раз: `/mybots` → бот →
Bot Settings → Menu Button → адрес. После этого кнопка меню в чате с
ботом открывает Mini App; `initData` Telegram подписывает сам
(`supabase/README.md` §«Как проверяется, что человек — это он»).

Смена адреса (переименование репозитория) — правка в BotFather руками,
код не трогается.

### 7.4 Проверка публикации

- `curl -sI https://<user>.github.io/<repo>/` отвечает 200;
- в сборке нет ключа service-role, ключа Claude и токена бота
  (инвариант 1) — проверяет `scripts/check-dist.mjs` по `dist/` в
  workflow до deploy и в воротах после сборки: ищет строки `service_role`,
  `sk-ant-`, токен по форме и разбирает каждый JWT — роль в клейме должна
  быть `anon`;
- открытие из Telegram показывает список задач владельца.
