# §27. Бот в MAX

Как Соломон получает переписку из MAX. Личные чаты MAX официально не
читаются (разведка 2026-10-07): бот в MAX — отдельный собеседник, он
видит только написанное ему самому и группы, куда его добавили.
Решения владельца: официальный бот; всё, что нашлось, — в обычный чат с
Соломоном в Telegram; группы, куда владелец добавит бота, тоже читать.
Разбор, хранение, согласие и что видит владелец — общие, §25. Код —
`services/max_bot.py` (этап 027).

### 27.1 Что делает владелец

Регистрирует бота на business.max.ru (самозанятый, подтверждение через
Госуслуги, модерация до 48 часов), кладёт в `.env` `MAX_BOT_TOKEN` и
свой id в MAX — `OWNER_MAX_ID` (инвариант 2). Нужны обе: нет хотя бы одной
— источник выключен, бот работает как раньше (в журнале — строка, если
задана только одна); `OWNER_MAX_ID` не числом — запуск останавливается, как
у `OWNER_TELEGRAM_ID`. Своего id в профиле MAX нет: его печатает живой тест
(`pytest -m live -k max -s`, §27.5). Для групп — разрешить боту групповые
чаты в «Приватности» на платформе и назначить его в группе администратором
с правом «Читать все сообщения». Подписку на вебхук боту не заводят: с ней
MAX не отдаёт события опросом. Инструкция — в `README.md`, раздел «MAX».

### 27.2 Связь

HTTP API MAX (`platform-api2.max.ru`), ключ — в заголовке
`Authorization` как есть, без `Bearer`; обновления — long polling отдельной
задачей asyncio в том же процессе бота, рядом с опросом Telegram
(`MaxService.start`, останавливается вместе с ботом — `stop`). Свой клиент
на httpx (`HttpMaxApi`) — без новой библиотеки. Сертификат
`platform-api2.max.ru` выдан российским удостоверяющим центром (Минцифры),
которому сервер не доверяет: проверка 2026-10-07 — `curl` ошибка 60.
Корневой сертификат (Russian Trusted Root CA, SHA-256
`D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`,
до 2032-02-27) лежит в `bot/certs/` и добавляется к обычным корневым только у
клиента MAX (`max_ssl_context`): проверка имени и цепочки не отключается,
другие клиенты бота его не знают, на сервере ничего не ставится. Отпечаток
держит тест; откуда файл — `bot/certs/README.md`.

**Опрос.** `GET /updates?limit=100&timeout=90&types=…&marker=…`: MAX держит
пустой запрос до 90 с (предел API), чтение клиента ждёт 105 с. Отметка
(`marker`), переданная в запросе, подтверждает всё до неё, поэтому бот
передаёт только отметку записанной пачки: MAX не ответил — пауза 5 с,
дальше вдвое до минуты, и та же отметка, пропущенное приходит снова; база не
записала пачку — та же пачка ещё раз, третья неудача подряд — пропуск и
строка в журнал. Между опросами — не меньше 300 мс (требование MAX). Ключ
отвергнут (401) — строка в журнал с именем `MAX_BOT_TOKEN`, опрос идёт
дальше. Отметка живёт в памяти процесса: после перезапуска MAX отдаёт
неподтверждённое, повтор база не хранит дважды.

MAX советует для боевой работы вебхук, а не опрос (опрос «ограничен по
скорости и сроку хранения событий»). Вебхуку нужен входящий адрес, которого
у бота нет (§16.6); для одного владельца опроса хватает. Долгий простой бота
может потерять события, которые MAX уже не хранит.

### 27.3 Что бот принимает

- **Личный чат владельца с ботом**: пересланные сообщения — строки
  переписки с исходным отправителем; чат — исходный чат пересланного
  (`from:<chat_id>`), а если MAX его не назвал — отправитель
  (`user:<user_id>`), имя чата — собеседник. Своё пересланное — строка
  «Вы» (`out`) того же чата. Своё сообщение владельца боту и подпись к
  пересылке — строка «Вы» в чате «MAX: заметки» (`notes`). Голосовые —
  Deepgram (§9), подсказка — имя собеседника, у заметок — без подсказки.
- **Группы**, куда владелец добавил бота с правом читать все сообщения:
  сообщение `OWNER_MAX_ID` — `out`, остальные — `in`; чат — `group:<chat_id>`,
  имя — название группы. Читаются только группы, где есть владелец
  (`GET /chats/{id}/members?user_ids=…`, проверка раз в час): бота в группу
  может добавить кто угодно. Пересланное в группу — его текстом.

«Ждёт ответа» по MAX не ведётся вовсе — ни по пересланному, ни по
заметкам, ни по группам (решение владельца): бот не видит, ответил ли
владелец в самом MAX. Только договорённости. Согласие (§25.5) —
при первом сообщении владельца боту или «Начать» (`bot_started`); группа
площадку не включает — иначе после перезапуска она снимала бы остановку
бота владельцем. Пересланное до «Согласен» не хранится — его нужно переслать
снова (так и сказано в вопросе о согласии). «Остановить» бота в MAX
(`bot_stopped`) выключает приём, новое сообщение боту — включает.
- Сообщения от других людей в личный чат бота — молча пропускаются:
  площадка от них не включается, ничего не хранится и не отвечается.

**Время.** Времени исходного сообщения в пересланном API не даёт: строка
получает время пересылки, и «завтра» в старой переписке считается от него.
Тишина и срок хранения — по времени прихода (§25.1).

**Разбор и что видит владелец.** Дальше — общий путь §25 с площадкой `max`.
Разбор называет заметки и группу прямо: первая строка — «Заметки владельца
самому себе в MAX.» или «Переписка в MAX, группа «Дача».», правила — дело из
заметок — владельца, `with_whom` группы — «группой «Дача»», заметок — пусто.
Сообщение о заметках — «Из ваших заметок в MAX записал: …», о группе — «Из
переписки с группой «Дача» (MAX) записал: …».

**«Принял».** Первое записанное сообщение владельца боту после 20 минут
тишины в личном чате (по времени прихода, в памяти процесса) — бот отвечает
там одной строкой «Принял, итог пришлю в Telegram.» (`POST
/messages?user_id=<OWNER_MAX_ID>`), раз на пачку. Только о записанном
(инвариант 4): до согласия, повтор, группа, чужой — без ответа. Не ушло —
следующий опрос пришлёт; бот остановлен (403) — не пришлёт. Другого бот в
MAX не пишет: у клиента нет метода писать в чат, только человеку по id.

**Правка и удаление** (§25.1): `message_edited` меняет текст до разбора;
`message_removed` называет только id сообщения и чат — чаты недавних
сообщений процесс помнит (последние 1000), группу знает по id, остальное —
заметка.

### 27.4 Что не делает

- Не читает личные чаты владельца с другими людьми (юзербот отвергнут).
- Не отвечает в MAX ничего, кроме «Принял…», и не пишет в группы.
- Не ведёт «ждёт ответа» по MAX; каналы не читает.
- Не читает группы, где нет владельца.

### 27.5 API MAX: что используется

Источник — официальная схема OpenAPI `max-messenger/api-schema` (v0.0.33,
2026-09-18; dev.max.ru из сессии этапа не открывался). Время — миллисекунды
Unix в UTC. Ошибка — HTTP-код и `{code, message}`; некоторые методы отвечают
200 с `{success: false}` — тоже отказ. В журнал — код, без текста.

| Что | Запрос | Поля, которые читает бот |
| --- | --- | --- |
| События | `GET /updates` | `updates[]`, `marker` |
| Сообщение | `message_created`, `message_edited` → `message` | `sender.user_id`, `first_name`, `last_name`; `recipient.chat_id`, `chat_type` (`dialog`, `chat`, `channel`); `timestamp`; `body.mid`, `body.text`, `body.attachments[]`; `link` с `type: forward` — `sender`, `chat_id`, `message.text`, `message.attachments` |
| Вложение | `attachments[].type` | `audio` → `payload.url` (голосовое, качается без токена); `image` — снимок; `inline_keyboard` — не содержимое; остальное — прочее |
| Удаление | `message_removed` | `message_id`, `chat_id` |
| Бот запущен, остановлен | `bot_started`, `bot_stopped` | `user.user_id` |
| Группа | `GET /chats/{id}`, `GET /chats/{id}/members?user_ids=` | `title`; `members[].user_id` |
| «Принял» | `POST /messages?user_id=` | тело `{text}` |
| Бот (живой тест) | `GET /me` | `user_id` |

В группах `message_created` приходит, только если бот — администратор с
правом `read_all_messages`. У голосового есть и своя расшифровка MAX
(`transcription`), бот её не берёт: расшифровка — Deepgram, как у всех
площадок (§9).

**Замер.** Живого прогона на этапе 027 не было: токена бота в `.env` ещё
нет. Приёмка подтверждена тестами с подменённым API MAX
(`tests/test_max_bot.py`). Живой тест только читает: `GET /me` и `GET
/updates` без отметки (ничего не подтверждает) тем же клиентом и
сертификатом — проверяет TLS и токен и печатает id тех, кто писал боту.
Сверить при первом живом прогоне: что MAX кладёт `chat_id` в пересланное
из личного чата и шлёт ли сервер промежуточный сертификат (нет — к
корневому добавить Russian Trusted Sub CA).
