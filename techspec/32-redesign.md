# §32. Редизайн приложения

Как Mini App переходит на одобренное оформление
(`prototype/archive/000-redesign/`, одобрен 10.10.2026; правила — `design.md`
§1–§4). Владелец (2026-10-09): «очень крутой дизайн, а то невнятный»,
календарь, анимации, «дорого и богато». Делается двумя этапами:
034 — оформление, вкладки, «Дела» и карточка; 035 — «Сегодня»,
«Неделя», «Сферы» с часами. Выкладываются вместе, после 035.

Решения владельца (интервью этапа 034, 2026-10-11): первой открывается
вкладка «Сегодня»; сферу дела можно сменить в карточке («Изменить»).

### 32.1 Темы

Две темы на одной разметке: тёмная «Банк-люкс» и светлая «Тихая
роскошь» (токены — `design.md` §1). Выбор — «Как в Telegram» (по
умолчанию: тёмный Telegram — «Банк-люкс», светлый — «Тихая роскошь»),
«Банк-люкс», «Тихая роскошь»; меняется в ⋯ → «Настройки» →
«Оформление». Выбор хранится в `owner_settings` (новая колонка `theme`:
`auto` · `bank` · `quiet`), правится из приложения под RLS (§4.2) — как
настройка, а не через бота; смена темы Telegram при `auto` применяется
сразу (`themeChanged`).

Шрифты (Inter, Inter Tight, Lora — OFL) лежат в сборке Mini App,
только кириллица и латиница, `font-display: swap`; из Google не
грузятся. Новых зависимостей для движения нет: прокрутка цифр, полосы и
фон — свой CSS и маленький компонент (`RollingNumber`), при
`prefers-reduced-motion` — конечный вид сразу. Второй UI-kit не
заводится (`CLAUDE.md`).

Как сделано (этап 034):

- **Запись выбора** — функцией `save_theme(theme)` (§3.8): владелец из
  клейма, под RLS; прямой `update` без условия Supabase не пропускает, а
  id владельца у приложения нет. Права приложения на `owner_settings`
  сужены до `update (theme)` — пояс остаётся зеркалом `.env` бота.
  Выбор в «Оформлении» меняет вид сразу, а сохранённым считается по ответу
  базы; отказ — текстом, и выбор возвращается к прежнему.
- **Первый кадр** — по копии выбора на устройстве (`localStorage`) и схеме
  Telegram, до рендера; правда — в базе, приложение читает её при старте
  и поправляет тему, если отличается. Шапка, фон и нижняя полоса Telegram
  красятся в `--bg` темы (`setHeaderColor` с Bot API 6.9).
- **Вход** — `SettingsButton` (пункт «Настройки» меню ⋯, Bot API 7.0);
  «Оформление» встаёт поверх текущего экрана, тот остаётся смонтированным
  — открытая форма правки не теряет введённое. Своего входа в разметке нет.
- **Шрифты** — `@fontsource-variable` 5.3.0, переменные по оси `wght`
  (у Lora ещё курсив), в `miniapp/src/fonts/` с текстами лицензий;
  зависимостью пакет не ставится.
- **Токены** — имена прототипа (`--bg`, `--acc`, `--c-late` …), прежние
  `--accent`, `--urgent`, `--important`, `--guess` заменены ими же; тема —
  атрибут `data-skin` на `<html>`. Контраст обеих тем держит тест
  `miniapp/src/lib/contrast.test.ts`, читая значения из `styles.css`.

### 32.2 Вкладки и экраны

Вкладки «Сегодня · Неделя · Сферы · Дела»; открывается «Сегодня».
Экран «О себе» уходит в карточку «Без сферы и о себе» на «Сферах»
(записи памяти без сферы, правка — как сейчас, §8.4). Пустые состояния —
`design.md` §2.

- «Дела» (034): переключатель «По сроку / По сферам», строка — отметка
  сферы, суть, «сфера · срок» со значком (§29), метки; «Сделано» — только
  в карточке.
- Карточка (034): время крупно (у встречи — «14:00–16:00», §31), сфера,
  поля, напоминания, источник; «Изменить» правит и сферу — выбор из
  сфер владельца или «без сферы» (через `edit_task`, §11.2).
- «Сегодня», «Неделя», «Сферы» (035): §32.3.

Как сделано (этап 034):

- «Сегодня» и «Неделя» до 035 показывают одобренные пустые состояния всегда
  — данных у них ещё нет; выкладываются вместе с 035. «Сферы»: сфер нет —
  пустое состояние, есть — шапка «N из 12» без карточек сфер (их добавит
  035), чтобы владельцу со сферами не говорить «Сфер пока нет».
- «Без сферы и о себе» — последняя карточка «Сфер»: «1 дело · 6 записей о
  вас»; нет ни дел без сферы, ни записей — карточки нет. «О себе» в ней —
  записи памяти без сферы (`sphere_id is null`), правка прежняя (§8.4).
- Сферы приложение читает само (§3.17): живые, по порядку заведения; место
  — цвет из палитры темы (`design.md` §1, места 5–12 подобраны на
  реализации), монограмма в «Банк-люксе» — два знака из названия.
- Строка дела: «сфера · 📅 срок» у срока с часом, «🔔» у дня и части дня, у
  идеи и желания значка нет; слова срока — как у бота, у встречи с концом.
  «По сферам» — группы в порядке мест, «Без сферы» — последней.
- Карточка: время крупно — только у срока с часом, ниже день и
  длительность словами («· 2 ч»); строка «Изменить» под полями стала
  кнопкой между «Сделано» и «Удалить» (артборд 05). Сфера в форме — ряд
  вариантов с переносом; ключ `sphere_id` уходит, только если её сменили
  (§3.6, §11.2).

### 32.3 Часы в приложении

Часы по сферам считает **одна** функция базы — `sphere_hours`, общая для
бота и приложения (`CLAUDE.md` §«Слои»: бот и Mini App зовут одно и
то же). Логика — §31 (встречи по длительности, сессии переписки, без
двойного счёта в сфере, пояс владельца); бот переходит с
`services/hours.py` на неё, его ответы не меняются. Для «Сегодня» и
«Неделя» — вторая функция, `day_spans`: отрезки дня (встречи и сессии
переписки со сферой, без текста сообщений) — нить дня строится из них и
из дел. Обе — `security definer`: владелец из токена приложения, боту —
параметром (несовпадение с токеном — отказ); считают за любой промежуток.
Прямое чтение `chat_messages` у приложения закрыто — текст переписки ему
недоступен совсем (решения владельца 2026-10-11).

### 32.4 Что не делает

- Не меняет устройство данных дел, напоминаний и сфер сверх колонки
  `theme`, сферы в `edit_task` и функций часов.
- Не делает тему настраиваемой по цветам и шрифтам.
- Не добавляет действий в одно касание в строке дела («Сделано» — в
  карточке).
- Не показывает текст переписки в приложении.
- Не делает виджетов и уведомлений из приложения.
